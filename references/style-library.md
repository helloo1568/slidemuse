# 可复用风格库

用户要求“保存这套风格”“以后都用这个风格”“把这张图的风格存起来”时读取。目标是把**可复用的视觉系统**存下来，而不是保存当前任务的私有内容。

## 与四套选型的关系

S3 的四套缩略图总览选型不变（见 [style-options.md](style-options.md)）：每次新任务仍在四套演绎中选型。风格库只是这套选型的**候选池**：用户明确指定库中已有风格时，它可代替现场演绎，但必须在风格门禁中记录来源与该风格标识。

## 两处来源

| 来源 | 位置 | 说明 |
|---|---|---|
| 内置风格 | 随包保留：`vendor/codex-ppt/skills/codex-ppt/references/*.md` | 完整图片生成后端自带，随技能更新 |
| 用户自定义 | `${CODEX_PPT_HOME:-~/.codex-ppt-skill}/references/*.md` | 技能安装目录之外，重新安装不丢 |

两处都用目录扫描发现，**不注册、不在文档里登记**。同名时用户自定义文件优先并覆盖内置风格。用户自定义风格不得写入技能安装目录内的 `references/`。

内置风格（本轮随包保留 12 套）：`清爽专业风`、`创意杂志风`、`电子墨水杂志风`、`数据仪表盘风`、`科研答辩风`、`复古扁平插画风`、`手绘技术解释风`、`手绘白板风`、`温暖手工风`、`麦肯锡风格`、`党政红风格`、`教学课件风`。

## 提取风格系统

以**可见页面**为事实源：成品页图、已批准的样张、用户提供的图片；PDF/PPT/PPTX 先渲染成真实页面图再检查，不从结构、文字、XML 或元数据推断视觉。

一份风格文件包含：

| 字段 | 内容 |
|---|---|
| `style_name` | 简短可复用的风格名 |
| `best_for` | 适用场景与受众 |
| `visual_direction` | 一句话的视觉识别 |
| `canvas` | 比例、背景、构图、密度、留白 |
| `color_palette` | 主色、辅色、强调色、中性色及用法规则 |
| `typography` | 标题、正文、标注、层级、对齐与文字质量规则 |
| `layout_patterns` | 反复出现的页面类型与构图 |
| `layout_usage_rule` | 保持同一识别的前提下如何随页面作用改变版式 |
| `layout_blueprints` | 2–4 个可复用构图蓝图，按语义描述而非照抄某一页 |
| `visual_elements` | 允许与避免的图标、图示、卡片、纹理、装饰、照片、图表 |
| `image_treatment` | 照片、截图、图表、插画的处理方式 |
| `rendering_constraints` | 图像模型必须遵守的规则 |

JSON 结构按内置风格文件的 `GPT-Image-2 风格 Brief` 格式书写，可直接作为逐页提示的风格输入。

## 不保存的内容

- 用户原文、业务数据、个人信息、客户名、私有项目名、论文结果、逐字引语和页面文案。
- 作为风格依赖的源图或截图；风格文件必须自包含，不依赖外部文件。
- 可识别的 logo 或品牌名，除非用户明确要求可复用品牌风格。

## 命名与落盘

```text
${CODEX_PPT_HOME:-~/.codex-ppt-skill}/references/{style_name}.md
```

- 用 2–8 个汉字或简短中文短语命名，命名的是**可复用的视觉风格**，不是项目、客户、论文或活动。
- 避免人名、公司名、客户名、论文标题、临时任务名，以及“我的风格1”“好看风”这类含义模糊的名字。可用示例：`深色数据科技风`、`极简发布会风`、`柔和学术插画风`、`高密度咨询风`。
- 目录不存在时先创建。目标文件已存在时询问覆盖、合并或换名；与内置风格同名时说明自定义文件会覆盖内置，并确认后再保存。

## 交付说明

保存后报告风格名、落盘路径，并说明它存放在技能安装目录之外、重新安装不丢，以及后续如何引用（例如“以后可以说：用「深色数据科技风」生成这份 PPT”）。
