# 内容大纲：深度与质量自检

S1/S2 使用。这里的大纲是进入视觉设计前可审阅的逐页内容稿。它应让用户判断“说什么、凭什么、说明什么”，并足以让后续生图执行已确定的内容。

## 先确定整套回答

- 受众要理解或决定什么？用一个具体问题描述，不以“介绍某主题”代替。
- 整套材料能支持什么回答？哪些关键事实、比较或论证不可省略？
- 每页如何推动回答？写出页面作用与前后衔接，合并重复结论，避免把材料分段直接当页序。
- 现有材料和页数能否容纳完整回答？过短时建议缩小范围或调整页数；没有授权时不自行增加页数。材料薄弱时如实缩小结论，不补造背景、机制、效果或建议。

不强制使用“背景—方法—结果”目录。路演应支撑价值判断，课堂应帮助理解，论文汇报应交代方法与证据，视觉叙事也可以通过图像、对照和顺序完成解释。

## 页数预算

先按页面类型扣除封面与收束页，得到内容页数量 N，再检查材料能否填满：

- 普通内容页默认 3–5 条支撑要点，N 页的 3N–5N 只是初步预算；先扣除有理由的图表主导/简洁页，再按实际内容判断。材料要点多于 5N 时，先合并同类、下沉为讲稿或图表标注，仍超出则与用户确认拆页或缩小范围，不靠压缩每页要点塞进现有页数。
- 普通内容页材料明显不足且不属于已说明的密度例外时，检查是否页数过剩：合并页面、补充比较与解释，或与用户确认下调页数。不得用装饰、标题复述或并列数字填补空页。
- 页数由用户指定或授权推荐后才调整；不得自行增加页数，也不得为凑页数虚构内容。

## 页面类型与必答内容

每个内容页先声明一个页面类型（layout role）。类型决定该页最少要写清什么，同一类型可以有多页，但整套不得都使用同一版式。

| 页面类型 | 最少必答内容 |
|---|---|
| `cover` 封面 | 主题、用途或场合、必要署名 |
| `agenda` 目录 | 各章标题与页序；不承载实质论证 |
| `section-divider` 过渡 | 上一段已得出的结论与下一段要回答的问题 |
| `concept` 概念解释 | 定义、为什么需要它、一个可检验的例子或适用边界 |
| `process` 流程 | 起点与终点、各步骤的输入/输出或判断条件、存在时说明分支或失败路径，不虚构 |
| `comparison` 对比 | 被比较双方的口径、至少两个可比维度、差异方向与量级 |
| `timeline` 时间线 | 时间刻度、各节点事件、节点与结论的关系 |
| `data-evidence` 数据证据 | 数据来源与口径、图形表达的关系、结论及其适用边界 |
| `architecture` 架构 | 层次或模块、它们的关系、数据或流程流向 |
| `case-study` 案例 | 场景、做法、结果，以及与主结论的关系 |
| `summary` 小结 | 回收到整套回答、遗留问题与下一步 |
| `qa` 问答 | 预判问题清单或联系方式；不新增论证 |

页面类型只描述页面作用；视觉系统仍由风格门禁决定，两者互不代替。

## 每页内容稿

内容页按实际需要组织以下信息；不要求各项都是独立文本框：

| 项目 | 可审阅的内容 |
|---|---|
| 页面类型 | `cover`、`agenda`、`section-divider`、`concept`、`process`、`comparison`、`timeline`、`data-evidence`、`architecture`、`case-study`、`summary`、`qa` 之一 |
| 页面作用与问题 | 本页回答什么，与前后页如何衔接 |
| 标题与主要结论 | 清楚表达已获支撑的观点；主题型标题另写主要结论 |
| 支撑要点 | 普通页默认 3–5 条有区别的事实、比较、步骤或解释，例外按[密度规则](content-density.md)说明，逐条可核验；说明每条支撑主要结论的哪一部分 |
| 证据与来源 | 数字、案例、引语、方法或材料位置；标注文件页码、章节、表号或网页栏目等可定位信息 |
| 解释与边界 | 证据怎样支持结论；口径、条件及不能据此推出的判断。没有机制证据时用“观察到/提示”，不编造原因 |
| 页面实际展示内容 | 写出最终可见文案、图表数据/标签及必要口径。图形可承担解释，但须说明实际呈现的关系，不能只写“配图” |
| 可选讲稿 | 补充推导、细节或口头衔接；无法仅看页面理解的核心证据与边界不能全藏在讲稿里 |

封面、目录、过渡、小结和问答页只需各自的必答内容；过渡页只需衔接。单页任务在一页内完成适合其目的的回答。图表主导页可用准确图形、标题、标注和短解释承载内容，不为凑正文增加段落。

### 要点密度

普通内容页默认 3–5 条有区别的支撑要点。图表主导页可让数据图承担解释；简洁聚焦页和密集查阅页按[内容密度与画面验收](content-density.md)声明 `density.mode` 和理由。封面、目录、过渡、小结和问答按作用处理。

少于默认数量时先判断证据图是否已经完整表达，而非机械补字；多于默认数量时先判断阅读负担与用途。语义重复、孤立数字和标题复述不算独立支撑。实际图片必须保留来源、解释与必要边界；不以字数、文字占比或填满版面代替论证深度。

论文/长文的机制、实验、目标与效果、来源冲突按需参照 [material-reading.md](material-reading.md)。内容确认后已有可选讲稿按 [speaker-notes.md](speaker-notes.md)保留到交付；导出检查不替代语义判断。

## 两道不同的门禁

先进行 Agent 内容质量自检，再展示给用户确认；明确授权内容代定时，在展示和自检后按授权范围继续。

| 自检项 | 判断方法与需要修正的情形 |
|---|---|
| 目标覆盖 | 整套回答受众的核心问题；关键问题遗漏或结尾未回应目标时修正 |
| 页间推进 | 每页承担有用作用；重复结论、数据并列却无比较、章节断裂时修正 |
| 要点密度与页面类型 | 普通内容页有明确页面类型与默认 3–5 条支撑；例外有合理用途和理由。重复标题、孤立数字、来源不明或实际画面省略解释时修正；非内容页按作用判断 |
| 论证深度 | 内容页的支撑和解释足以支持主要结论；只有口号、标题复述、孤立数字时修正。简洁页面注明其作用 |
| 事实与口径 | 证据可定位，时间、单位、样本及统计对象一致；衍生计算写明输入与公式，推断标明性质。缺失来源或越界因果时修正 |
| 可见内容完整 | 页面展示内容足以理解结论，必需信息没有藏进讲稿；不能等到生图时临时决定正文 |
| 篇幅与待确认项 | 内容在指定页数内可读；阻塞主结论的缺口已解决，或缩小到证据支持的范围。可选补充和非阻塞缺口明确记录 |

在 `deck-spec.md` 记录当前内容版本、各项判断、问题页和处理结果。未通过留在 S1；需要用户提供关键材料时展示具体缺口并等待，不先生成风格。修正后重新审阅受影响项，不能以“字段已填满”宣告通过。

### 在内容门禁前停止

大纲定稿并自检通过后，展示整套叙事、每页类型与结论、实际展示内容和待确认项，然后停在该门禁：

- 报告大纲位置、页数、页面类型清单与素材图→页映射，并如实说明当前是否已生成图片/PPTX（恢复任务保留已有产物，不宣称不存在）。
- 用户确认或明确内容代定授权之前，不得创建 `page-spec.json`、风格总览、生图提示、成品图片或 PPTX，也不得开始风格或生图后端讨论。
- 需要预留内部草稿时，文件名带 `draft` 并明确说明不是定稿。

内容稿自检通过不等于用户批准。确认或代定授权要能对应当前版本和范围；沿用上下文中已经明确的授权，不要求特定措辞。内容代定不自动包含风格代选或可编辑交付授权。自检是 Agent 的语义判断，Page Spec 校验和交付评分脚本不能证明大纲深度合格。

## 简短反例与修正

以下为虚构训练材料：报告表 2 记载某走廊公交客流同比 -5%、轨道客流同比 +3%，统计期与单位相同，没有出行者转移或原因数据。

**过浅**：标题“公交与轨道”，页面类型未声明，正文只有“-5% / +3%”，结论“轨道抢走公交客流”。数字并列没有展开比较，只有 2 条要点，结论也超出证据。

**可审阅的内容稿**：

- 页面类型：`data-evidence` 数据证据。页面问题：两种方式的客流变化是否一致？承接总量页，为后续分方式讨论提供依据。
- 标题/结论：公交与轨道客流呈相反变化。
- 支撑要点（4 条）：
  1. 公交客流同比 -5%，轨道客流同比 +3%，统计期与单位相同（报告表 2）。
  2. 两者方向相反，差距为 `3 - (-5) = 8` 个百分点，是衍生比较。
  3. 未提供基期人数，无法由两种同比增速判断走廊总客流增减。
  4. 这些总量变化不能证明乘客从公交转向轨道；转移需要同一人群的出行追踪数据。
- 页面展示：同口径两根增长率柱，标签“公交 -5%”“轨道 +3%”；短解释“轨道增速高于公交 8 个百分点”；口径与来源“某走廊，同期同比，报告表 2”；边界“不能据此推断乘客转移”。
- 可选讲稿：若要研究转移，需要同一人群的出行追踪等补充证据；当前材料未提供。

这页增加了比较、解释和结论边界，4 条要点里两条是比较与解释、一条是边界，不依赖填满版面。材料仅有这些数据时，后续页也不能把待检验的原因写成已证实机制。
